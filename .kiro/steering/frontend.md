# frontend.md — フロントエンドステアリング

Next.js 側の設計方針。**バックエンドと同じく、フロントの設計もこのプロジェクトの成果物として扱う。**

## 【重要】Next.js 16 を記憶で書かない

**Next.js 16 はトレーニングデータ上の慣習と異なる破壊的変更を含む。**
コードを書く前に `frontend/node_modules/next/dist/docs/` を参照すること。

本ファイルに書いてあるのは**設計方針**であり、API の具体的な作法ではない。
方針を実装に落とす時点で、必ず上記のドキュメントで現行仕様を確認する。

---

## 1. 責務の境界

Next.js は**画面と、認証の中継（BFF）だけ**を持つ。業務ロジックと認可判断は持たない（ADR-0010 / ADR-0014）。

| 持つ | 持たない |
|---|---|
| 画面・コンポーネント | 業務ルール（状態遷移の可否、公開の条件） |
| Cookie ⇄ `Authorization` の載せ替え | **認可の判断** |
| 未ログイン時のリダイレクト | データの加工・集約 |

**判定基準：BFF のコードが `contents` や `publications` の業務ルールを知り始めたら越境。**

### 権限による表示制御の位置づけ

権限のないボタンを画面から隠すのは **UX のため**であって、防御ではない。
**防御は API 層で行う**（tech.md セキュリティ、E9）。

> 画面で隠す ＝ 親切
> API で拒否する ＝ 防御
> **両方やる。片方だけにしない。**

## 2. 状態の3分類 ★最重要

このアプリは性質の違う状態が3種類あり、**混ぜると必ず壊れる。**

| 種類 | 例 | 置き場所 |
|---|---|---|
| **サーバー状態** | ネタ一覧、コンテンツ本文、指標ダッシュボード | データフェッチ層のキャッシュに任せる。自前で複製しない |
| **プッシュ由来のサーバー状態** | 編集ロックの保持者、レビューコメントのライブ反映、ジョブ進捗 | **WebSocket / SSE の受信を、上と同じキャッシュに流し込む** |
| **クライアント状態** | エディタの編集中バッファ、モーダルの開閉、絞り込み条件 | ローカルに閉じる。サーバーへ送るまで外に出さない |

**2行目が肝。** ADR-0004 で Yjs を捨てた以上、「他人が今どこを編集中か」の整合は自前で取る必要がある。
ここで受信データを別の入れ物に持つと、**画面の状態とサーバーの状態が二重管理になり、必ずズレる。**
プッシュで来た更新は、フェッチで得た結果と**同じキャッシュを更新する**形に統一する。

### 編集中バッファの扱い

エディタの編集中テキストは**クライアント状態**であり、サーバー状態のキャッシュを直接書き換えない。
保存時に楽観ロック（ADR-0004）のバージョン番号を添えて送り、**競合したら差分を提示する。**
「送信中に他人の更新が届いた」を扱えるよう、この2つは別物として保持する。

## 3. Server Component / Client Component の境界

`"use client"` の境界がそのままコンポーネント設計になる。**境界は下に押し下げる**（ページ全体をクライアントにしない）。

| サーバー側 | クライアント側 |
|---|---|
| 一覧・ダッシュボードの初期表示 | Markdown エディタ |
| 初回データ取得（BFF 経由） | WebSocket / SSE の購読 |
| 認証状態によるリダイレクト | グラフ・チャート |
| | フォーム、絞り込み、モーダル |

**原則：データを取ってくる層はサーバー、対話する層はクライアント。**
クライアントコンポーネントは受け取った props を描画することに集中させ、**その中でさらにフェッチを始めない。**

---

## 4. バックエンドとの契約：OpenAPI からの型生成

**フロントの型は手書きしない。** FastAPI が生成した OpenAPI から起こす（tech.md）。

- 生成物はコミットする（差分がレビューで見える状態にする）
- **生成を CI に組み込み、スキーマとズレたら落とす**
- これは ADR-0001 で tRPC を捨てた分の埋め合わせ。バックエンドの `import-linter` と同じ発想で、
  **規約ではなく仕組みで守る**

## 5. ディレクトリ構造

```
frontend/
├── app/                    ルーティング（Next.js App Router）
│   ├── (auth)/             ログイン・招待受諾
│   ├── (app)/              ログイン後の画面
│   └── api/                BFF：認証の中継のみ（ADR-0014）
├── components/
│   ├── ui/                 汎用（ボタン・ダイアログ等）。ドメインを知らない
│   └── {domain}/           ドメイン単位（contents / reviews / metrics …）
├── lib/
│   ├── api/                生成された型 ＋ フェッチのラッパ
│   ├── realtime/           WebSocket / SSE の購読とキャッシュへの反映
│   └── auth/               Cookie の読み書き（サーバー側のみ）
└── types/                  OpenAPI からの生成物
```

**`components/ui/` はドメインを知らない。** ここに `Content` や `Publication` の型が出てきたら置き場所を間違えている。

# product.md — プロダクトステアリング

## Reverb とは

**「書いたあとに何が起きたか」を記録し続けるための箱。**

Obsidian の断片ノートから、記事ネタ・執筆・レビュー・公開を経て、**反応の日次追跡**までを1本のパイプラインにする。Qiita・note・X・ポッドキャストという複数の発信チャネルを、同じ器で横断的に扱う。

名前の由来は「残響」——発信したあとに返ってくるもの。

## 解く課題

| 課題 | 解決 |
|---|---|
| ネタが散らばり、どれが記事になったか分からない | ネタを在庫として状態管理し、公開物まで線でつなぐ |
| 「あの断片メモがこの記事になった」履歴が残らない | 1つのコンテンツが受信箱から公開まで一貫して状態遷移する |
| Qiita・note・Spotify の数字を各サイトで別々に見るしかない | 全チャネルの指標を1画面に集約する |
| **各プラットフォームは「現在値」しか見せない** | **日次スナップショットを取り続け、推移を保存する** |
| 学んだことを記事に適用した結果が測れない | タグ別・曜日別・文字数帯別に反応を比較できる |

**4つ目が本質。** 日次でスナップショットを取り続けない限り、「公開後3日で伸びた／じわじわ伸びた」の区別は永久につかない。これが Web アプリである必然性であり、データが構造的に大量になる理由でもある。

## ユーザー

| アクター | 説明 |
|---|---|
| オーナー | 主たる利用者（＝開発者本人）。全操作が可能 |
| 共同編集者（editor） | 招待されたメンバー。執筆・編集はできるが公開はできない |
| レビュアー（reviewer） | 招待されたメンバー。閲覧とコメントのみ |
| Claude Code | ローカルで動くエージェント。MCP 経由でサービスを操作する |
| デモ閲覧者 | デモ用の読み取り専用アカウント |

**一般ユーザーの自己登録は無効（招待制）。** これによりプライバシーポリシーの整備が不要になる。

## 判断基準

迷ったら以下に戻る。

1. **初見の人が README を読んで、何を作ったか理解できるか**
2. **4ヶ月で完成するか**（未完成の大作より、完成した中規模）
3. **設計判断の理由を自分の言葉で説明できるか**（選んだ理由、詰まった点、解決方法）
4. **生成AI活用が自然に組み込まれているか**（後付けにしない）

## 本プロジェクトで扱う技術領域

意図的に以下8つを扱う設計にしている。ただし**すべてが実際に使う機能から自然に出ていること**が条件で、領域を埋めるために機能を足さない。

| 要素 | 担い手 |
|---|---|
| 生成AI | チャネル変換（Qiita ⇄ note ⇄ X 280字）、タグ提案 |
| 外部API | Qiita API（投稿＋指標）、note、ポッドキャスト RSS |
| 認証・認可 | 企画の3ロール ＋「公開は owner のみ」＋ MCP サーバー認証 |
| DB設計 | contents ↔ tags 多対多、6状態の遷移、リビジョン履歴、指標スナップショット |
| パフォーマンス | 50万行の指標スナップショットに対する集計とインデックス設計 |
| リアルタイム | 編集ロックの取得・解放、レビューコメント、ジョブ進捗 |
| 非同期 | 日次指標取得（キュー・リトライ・レート制限）、LLM 変換ジョブ |
| 複雑SQL | 公開後 N 日の伸びカーブ、タグ別・曜日別集計、公開月コホート |

## 削ってはいけないもの

スコープを削る場面で、**以下を削ると上記8領域のいずれかが失われる。**

- 企画の共有と下書きレビュー（＝**認可**の担い手）
- 編集ロック／楽観ロックとレビューコメントのライブ反映（＝**リアルタイム**の担い手）
- 日次スナップショットと時系列分析（＝**パフォーマンス**と**複雑SQL**の担い手）
- MCP サーバー（＝**API 設計**の中核）

## やらないこと

| 項目 | 理由 |
|---|---|
| note への自動投稿 | 公開 API が存在しない |
| **Obsidian への書き戻し（双方向同期）** | 必ず破綻する。**一方向のみ** |
| ポッドキャスト音声の文字起こし・音声処理 | スコープ外。公開 URL と指標だけ扱う |
| iframe による各プラットフォームの埋め込み | 各社が `X-Frame-Options: DENY` を返す。同一オリジンポリシーで DOM も操作できない |
| **ブラウザ内ターミナル（xterm.js + node-pty）** | 出力が構造化データにならない。公開デプロイに RCE 面を作ることになる |
| Instagram 連携 | Meta のアプリ審査＋画像の公開 URL ホストが必要で見合わない |

## 【重要】Next.js 16 について

**Next.js 16 はトレーニングデータ上の慣習と異なる破壊的変更を含む。**
コードを書く前に `frontend/node_modules/next/dist/docs/` を参照すること。記憶で書かない。

## アーキテクチャ制約

### 依存方向（厳守）

```
Controller → Service → Repository
```

**下位レイヤーが上位を参照することは禁止。** Controller に業務ロジックを書かない。Repository に業務判断を持ち込まない。

**Service は Request / Response を知らない。** `@Req()` を Service まで持ち込まないこと。持ち込むと HTTP に依存し、MCP サーバーとジョブから呼べなくなる。

理由の詳細は ADR-0009。**入り口が3つ（ブラウザ / MCP / ジョブ）あるため、業務ルールと認可を Service に集約しないと二重実装になる。**

### 共同編集の実装方針

**Yjs（CRDT）を使わない。**

ライブラリが排他制御を全部引き受けてしまい、バックエンドの設計が成果物として残らないため。代わりに以下を自前で設計する。

- **セクション単位の編集ロック**（取得・解放・タイムアウトによる自動解放）
- **楽観ロック**（バージョン番号による競合検出）＋ 競合時の差分提示

### エディタの実装方針

**Markdown エディタは既製品を組み込むだけ。自作しない。**
フロントの作業であり、このプロジェクトで扱いたいバックエンドの設計とは無関係。

### 外部チャネル連携

`ChannelAdapter` インターフェースの `capabilities.publish` で3モードを表現し、UI とジョブの分岐を1箇所に集約する。

| モード | 対象 | 挙動 |
|---|---|---|
| `auto` | Qiita | API 経由で投稿・更新まで完全自動 |
| `intent` | X | Web Intent で本文入りの投稿画面を開く。**API キー・OAuth 不要** |
| `manual` | note / ポッドキャスト | 整形済み本文をコピー＋公開画面を開く → 公開後に URL を貼り戻す |

**X と Instagram の API 条件は変更が頻繁。実装時に必ず最新仕様を確認する。**

### MCP サーバー

サービスの API を MCP サーバーとして公開し、**ローカルの Claude Code から叩く。**

- 公開ツール：`list_ideas` / `create_content` / `update_content` / `search_published` / `get_metrics` / `publish`
- **トークン認証必須。認可は画面と同一のロジックを通す**
- **サービス側から Obsidian Vault へは一切アクセスしない**（Vault はローカルにあり、AWS からは物理的に到達できない）

## 非機能要件

### パフォーマンス

| 項目 | 目標 |
|---|---|
| 指標スナップショットの想定件数 | **50万行** |
| ダッシュボード初回表示 | 1秒以内 |
| 分析クエリ（タグ別・コホート） | 2秒以内 |

**数十万行をシードして実測し、README に Before/After を掲載する。**
インデックス設計、日次生データと月次ロールアップの持ち分け、パーティショニングの要否を ADR に残す。

### セキュリティ

| 項目 | 方針 |
|---|---|
| 外部サービスのトークン | **アプリケーション層で暗号化して保存。平文保存しない** |
| MCP サーバー | トークン認証必須 |
| 権限チェック | **API 層で拒否する。画面で隠すだけにしない** |
| 一般登録 | **無効（招待制）** |
| Obsidian 取り込み | 対象フォルダを明示的に限定する（日記・気分の記録を巻き込まない） |

## 開発標準

- **テスト**：ユニット（Service / Repository）＋ 結合（API エンドポイント）
- **API 仕様**：OpenAPI で公開
- **ADR**：設計判断は `docs/adr/` に残す。**時間が経つと「なぜこうしたか」は必ず忘れる**
- **CC-SDD**：`.kiro/specs/` をリポジトリに含める（要件と設計の経緯を残すため）

## LLM を扱うときの注意

Claude API を呼ぶコードを書く前に、**`/claude-api` スキルを読むこと**。モデル ID・パラメータ・SDK の使い方を記憶で書かない（2025〜2026 に破壊的変更が複数入っている）。

# ADR-0010: フロントエンドとバックエンドを分離する

- **日付**: 2026-08-26
- **ステータス**: 採用

## 背景

Next.js を使う以上、API を Next.js の Route Handlers に持たせて1つのアプリにまとめる選択肢がある。
一方このアプリには**入り口が3つある**（ブラウザ / MCP サーバー / 日次バッチ）。

## 選択肢

1. **分離する** — Next.js（フロント）と NestJS（API）を別アプリにする
2. 統合する — Next.js の Route Handlers に API を持たせる

## 決定

**分離する。**

```
ブラウザ ──┐
Claude Code ├──→ NestJS API ──→ PostgreSQL / Redis
ジョブ ─────┘
```

## 理由

### API が Next.js のランタイムに依存してはいけない

MCP サーバーとジョブは、ブラウザとは無関係に API を叩く。
Route Handlers に寄せると、**これらが Next.js のランタイムに依存する。**

### API を独立して読める状態にしておきたい

バックエンドの設計がこのプロジェクトの中心なので、
**API が単体で読める・単体でテストできる・単体でデプロイできる**ことに意味がある。

### 却下した理由（統合案）

統合すれば構成はシンプルになり、型もそのまま共有できる。
ただし上記2点を満たせないため採用しない。

## 影響

- **CORS の設定が必要になる**
- 認証はトークンをフロントで保持し、リクエストに付与する形になる
- **デプロイ対象が2つになる。** インフラ構成（ADR-0003）でこれを織り込む必要がある
- 型の共有は OpenAPI からの生成で担保する（ADR-0001 で tRPC を捨てた分の埋め合わせ）
